# Content-free analytics contract v1

Written by Codex, 1 October 2026. The executable property allowlist is `Habits/Analytics/AnalyticsContract.swift`. The report remains the product plan; this document records the implemented boundary.

## Shared semantics

Use the same event names, enums and integer counters on future clients. Only the iPhone adapter exists. Widget callbacks exist for the consolidated iPhone app and extension. Reserved `watch`, `web` and account semantics are vocabulary, not implemented coverage. `entity_created` means a successful durable new user creation, with `entity_type=habit|task`; task has `habit_type=not_applicable`. Habit types are `check`, `amount`, `duration`, `checklist`, `quit`, `cut_down`; an amount or duration habit with an upper limit is cut_down. Imported/restored/replicated rows do not count as new creations or tracking actions.

A successful tracking write is counted after persistence acknowledges it. Classify the effective historical habit rule and the originating action. Retries retain a random operation guard; correction/undo counters are separate. Task reopening is a correction, not another completion. Activation means first **observed after consent** tracking write; provenance is fresh_first_run only for a welcome actually observed after consent, restored only after an observed successful durable restore, and otherwise unknown. Never present it as lifetime-first. Each future account/purchase/restore adapter must capture consent generation at initiation, emit only its verified terminal result and pass the existing restricted result allowlist. Do not wire the disabled Plus buttons to synthetic successes.

Three envelopes close an active UTC day: `feature_usage_daily`, `screen_engagement_daily`, `configuration_snapshot`. External-only days need only the feature envelope. Freeze on the next eligible lifecycle/action, once; no midnight/background telemetry wakeups. Daily collection start/end and partial-day, sampling, coverage and loss properties are explicit. Coverage v2 zero-fills only the explicit working iPhone adapter registry, enabling unused-feature denominators. Reserved delete-entry/completed-filter/year-share counters and watch/web origins remain absent/unknown. Earlier coverage versions are excluded from v2 adoption ratios. Capability false means unavailable, never unpopular. `coverage_complete=false` remains accurate for this partial platform/feature implementation.

Screen visits and estimated attention use fixed screen enums and a monotonic clock. Attribute the topmost measured surface only while foreground, unlocked and within 30 seconds of native interaction. Stop at idle, background, lock or an unmeasured modal. Native touch observation captures no coordinates, targets, text or keys. Keyboard/VoiceOver-only activity may be underestimated. Running timer time never extends attention. No observable clock or history scan runs in view drawing.

## Privacy and delivery

Usage consent is optional and initially off. No identity, counters, files or queue are created before consent. Tickets from before opt-in or a previous consent generation are rejected. Opt-out revokes synchronously, cancels delivery and deletes the disposable ledger; a later opt-in creates a new random installation identity. A provider request already received cannot be recalled. Crash consent is separate and disabled because no crash collector is initialized in consolidated integration. No duplicate crash SDK is added.

Never pass application models, names, notes, goals, values, schedules, identifiers, tokens, paths or errors to telemetry. Only fixed enums, bounded aggregate integers and booleans pass validation; validate again at serialization. UUIDs identify installations and telemetry records, never accounts or business objects. The independent telemetry directory is excluded from device backup, exports, account requests and restore. UserDefaults holds app choices; telemetry takes only their controlled state, not values such as day-start hour or user-entered reminder times.

The only client key is the public PostHog **project capture** key. No personal/admin API key belongs in the app. Explicit HTTP batches use the EU endpoint, ephemeral sessions, no cookies, cache, credentials or custom tracing headers. `$process_person_profile=false`, `$geoip_disable=true` and a zero IP are sent. No analytics SDK is initialized; no autocapture, replay, profile updates, feature flag evaluations or crash collector runs. Project defaults were also disabled via confirmed provider calls.

Outbox: at most 256 records, at most seven days, 512KB persisted state; operation guard: 1,024 keys; counters saturate at 100,000. Explicit low-frequency events are additionally capped at 100 per collection day, with loss reported. Metadata is frozen with each record and open collection period so app/OS/sampling upgrades cannot relabel queued observations or daily summaries; development records are discarded on a release upgrade. Successful provider acknowledgements remove only that batch's IDs; retries reuse exact record IDs/payloads, with 60s–1h backoff and no scheduled wake. Invalid HTTP 400/413 records are dropped; other failures retain the bounded queue. Telemetry failure never alters durable app tracking or backup outcomes.

All events and envelopes share one stable random installation sampling bucket and version. Default probability is 1 for the currently empty project. Reduce a whole-installation cohort consistently as volume grows; do not sample only successful flow outcomes. There is no global quota guarantee from per-device caps. Published Product Analytics free allowance is 1M events/month; planning ceiling is 700k. The owner confirms the sole Default project has no billing configured. Billing allowance, organization usage and spend-cap enforcement are **not API-verified** because billing:read is unavailable. No paid service was enabled. Check projected usage weekly and after releases.

## Consolidated onboarding, help and widget adapters

Welcome offers an optional link to Privacy; declining never blocks onboarding/tracking. Only steps that appear after consent count, once per step per flow. Replay is separate; creation completion waits for the durable store flush. Suggestion provenance is a Boolean, never an idea name. Existing installations whose welcome was suppressed have unknown onboarding outcome. Help counts opening an answer, first search use, contact initiation and replay without questions, queries or email content.

Widget accepted tracking is counted after SQLite commits and passes persistent callback-ID retry guards. Widget deep links count actual app URL callbacks; no item identifier leaves the app. The extension observes successful paging writes through a 4KB bounded, excluded-from-backup content-free App Group mailbox. It mirrors consent with a random generation, caps counts at 100,000 and rejects stale callbacks; opt-out removes it. Drain is at-most-once; termination may lose counts, and older-day paging is dropped instead of reassigned. Neither extension nor widget provider sends network analytics or emits impressions.

Main-app WidgetCenter queries count fixed kinds/families, never selected entities, keys, instances or content. Placement is unknown; queries can fail. Only changed inventory snapshots emit, at most once per UTC day, guarded persistently across cold starts. Stale/absent snapshots are not removals. Widget snapshot publication reliability is separate from accepted habit writes and does not prove iOS displayed a widget. Widget privacy reports effective hidden/visible state and default/user-selected choice separately; app lock may force hiding. Capability-set and measured daily coverage are version 2. Accounts, sync, StoreKit verified purchases and future platforms remain outside actual adapter coverage.
