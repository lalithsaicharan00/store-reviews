# Content-free analytics contract v1

Written by Codex, 1 October 2026. The executable property allowlist is `Habits/Analytics/AnalyticsContract.swift`. The report remains the product plan; this document records the implemented boundary.

## Shared semantics

Use the same event names, enums and integer counters on future clients. Only the iPhone adapter exists. Reserved `widget`, `watch` and `web` origins and screen names are vocabulary, not implemented coverage. `entity_created` means a successful durable new user creation, with `entity_type=habit|task`; task has `habit_type=not_applicable`. Habit types are `check`, `amount`, `duration`, `checklist`, `quit`, `cut_down`; an amount habit with an upper limit is cut_down. Imported/restored/replicated rows do not count as new creations or tracking actions.

A successful tracking write is counted after persistence acknowledges it. Classify the effective historical habit rule and the originating action. Retries retain a random operation guard; correction/undo counters are separate. Task reopening is a correction, not another completion. Activation means first **observed after consent** tracking write; provenance is currently unknown, so it is never presented as lifetime-first or fresh onboarding activation. Each future account/purchase/restore adapter must capture consent generation at initiation, emit only its verified terminal result and pass the existing restricted result allowlist. Do not wire the disabled Plus buttons to synthetic successes.

Three envelopes close an active UTC day: `feature_usage_daily`, `screen_engagement_daily`, `configuration_snapshot`. External-only days need only the feature envelope. Freeze on the next eligible lifecycle/action, once; no midnight/background telemetry wakeups. Daily collection start/end and partial-day, sampling, coverage and loss properties are explicit. A missing counter is unknown/unobserved unless its current adapter and denominator are established. Capability false means unavailable, never unpopular. `coverage_complete=false` remains accurate for this partial platform/feature implementation.

Screen visits and estimated attention use fixed screen enums and a monotonic clock. Attribute the topmost measured surface only while foreground, unlocked and within 30 seconds of native interaction. Stop at idle, background, lock or an unmeasured modal. Native touch observation captures no coordinates, targets, text or keys. Keyboard/VoiceOver-only activity may be underestimated. Running timer time never extends attention. No observable clock or history scan runs in view drawing.

## Privacy and delivery

Usage consent is optional and initially off. No identity, counters, files or queue are created before consent. Tickets from before opt-in or a previous consent generation are rejected. Opt-out revokes synchronously, cancels delivery and deletes the disposable ledger; a later opt-in creates a new random installation identity. A provider request already received cannot be recalled. Crash consent is separate and disabled because no crash collector is initialized in consolidated integration. No duplicate crash SDK is added.

Never pass application models, names, notes, goals, values, schedules, identifiers, tokens, paths or errors to telemetry. Only fixed enums, bounded aggregate integers and booleans pass validation; validate again at serialization. UUIDs identify installations and telemetry records, never accounts or business objects. The independent telemetry directory is excluded from device backup, exports, account requests and restore. UserDefaults holds app choices; telemetry takes only their controlled state, not values such as day-start hour or user-entered reminder times.

The only client key is the public PostHog **project capture** key. No personal/admin API key belongs in the app. Explicit HTTP batches use the EU endpoint, ephemeral sessions, no cookies, cache, credentials or custom tracing headers. `$process_person_profile=false`, `$geoip_disable=true` and a zero IP are sent. No analytics SDK is initialized; no autocapture, replay, profile updates, feature flag evaluations or crash collector runs. Project defaults were also disabled via confirmed provider calls.

Outbox: at most 256 records, at most seven days, 512KB persisted state; operation guard: 1,024 keys; counters saturate at 100,000. Explicit low-frequency events are additionally capped at 100 per collection day, with loss reported. Metadata is frozen with each record so app/OS/sampling upgrades cannot relabel queued observations; development records are discarded on a release upgrade. Successful provider acknowledgements remove only that batch's IDs; retries reuse exact record IDs/payloads, with 60s–1h backoff and no scheduled wake. Invalid HTTP 400/413 records are dropped; other failures retain the bounded queue. Telemetry failure never alters durable app tracking or backup outcomes.

All events and envelopes share one stable random installation sampling bucket and version. Default probability is 1 for the currently empty project. Reduce a whole-installation cohort consistently as volume grows; do not sample only successful flow outcomes. There is no global quota guarantee from per-device caps. Published Product Analytics free allowance is 1M events/month; planning ceiling is 700k. The owner confirms the sole Default project has no billing configured. Billing allowance, organization usage and spend-cap enforcement are **not API-verified** because billing:read is unavailable. No paid service was enabled. Check projected usage weekly and after releases.

## Release verification

`Habits-Info.plist` selects EU Default project 290602; `AnalyticsProductionEnabled=false` keeps sending gated pending actual provider acceptance/deduplication verification. Debug, UI-test and performance fixtures never send to this sole production project. Share Usage may exercise local collection while delivery is gated; production rollout requires the gate plus explicit consent. Dashboards are prepared and their SQL validated against the empty project, which is not proof of delivery.

The environment receives HTTP CONNECT 403 for `eu.i.posthog.com`; the connector has no ingestion tool. Complete real consented release-device upload and provider row inspection in an authorized network, verify retry UUID behavior and profile/geoip suppression, then set the release gate true in a reviewed commit. Do not substitute a success claim based on a serialized payload or an empty dashboard.

The privacy manifest conservatively treats pseudonymous installation analytics as linked device ID, product interaction and bounded other diagnostics for analytics, without tracking. UserDefaults uses CA92.1; uptime is used only to measure elapsed app attention (35F9.1). No boot time is transmitted. App Store privacy answers must reflect eventual enabled collection; no store submission is part of this task.
