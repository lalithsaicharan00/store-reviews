# Codebook — App Lock and widget privacy (item 58), 8 Oct 2026
LIKE      praises having a lock            WANT      asks for a lock
FREE      says the lock being free matters PAYWALL   lock charged for / moved to paid
WHY_OTHERS reason: people who use or pick up the phone (family, partner, friends, kids, snoopers)
WHY_SENS  reason: sensitive content (self-harm, addiction, sobriety, mental health, sexual, embarrassment)
DISCREET  values a discreet app (name, icon, no notifications) or a neutral icon
RELOCK    about when it locks again (on leaving, timeout, grace period)
AUTOASK   about the prompt appearing by itself vs a tap
PEEK      content shown before the lock / in the app switcher / on resume
LEAK_WIDGET widget shows content while the app is locked     WIDGET_DISCREET wants/likes a widget without names
LEAK_NOTIF  notifications reveal content (or wants them private)
LEAK_OTHER  another surface leaks (Siri, search, share sheet, Watch, title of a locked note…)
BROKEN    lock bug: stuck on Face ID screen, crash, can't get in
LOCKOUT   locked out by a forgotten separate code/password (data lost or stuck)
FALLBACK  about passcode fallback / choosing Face ID vs code
SEPARATE  wants a code separate from the phone's (others know the phone passcode)
SYSTEMCODE likes/wants the phone's own passcode/Face ID rather than a new one
GRANULAR  wants to lock only some items (one habit, one note, one section)
ANNOY     lock is friction / asks too often / slows opening
ACCIDENT  lock prevents accidental changes
NR        not relevant
BYPASS    lock can be got round (restart, background, a path in) — distinct from PEEK (a glimpse)
BIOFEAR   distrust of giving an app a fingerprint/face (thinks the app stores it)
BIOWANT   has a typed app code and wants Face ID/Touch ID instead (typing it is the friction)
NOTNEEDED says an app lock is pointless (the phone is already locked)
WORKAROUND renames/obscures entries instead of a lock
SYSLOCK   mentions locking with iOS's own feature (Settings / Require Face ID) instead of the app's
CONFUSED  doesn't know which code/password the lock wants
WANTS_VISIBLE wants content shown on the Lock Screen / notifications / widget without unlocking (the other side)
SYSLOCK_WIDGET iOS's own app lock removed or broke the app's widgets
REMOVED   a lock the app had was taken away (and the reaction)
