# Navigation codebook (hand coding, one line per candidate: `idx<TAB>CODES<TAB>short note`)
Suffix + praise, - complaint, R request. A review can carry several codes. X = not relevant.

| Code | Meaning |
|---|---|
| DR+ / DR- / DRR | Hamburger / side drawer / side menu: praise / complaint / request |
| TB+ / TB- / TBR | Bottom tab bar / tabs / bottom nav: praise / complaint (too many tabs, clutter, wrong items, space) / request |
| RD | Navigation redesign complained about; note direction (e.g. drawer->tabs, tabs->drawer, moved item) |
| HID | A feature/setting is hidden, buried or hard to find (discoverability) |
| DEEP | Too many taps/screens/layers to reach something or to log |
| REACH | One-handed use / top of screen hard to reach / thumb zone |
| ONE | Praise or want everything on one screen / no navigation needed / minimal screens |
| NAV+ / NAV- | Navigation praised / criticised with no structural detail beyond "easy/confusing" |
| SWP | Swipe between tabs/pages/days (+/-) |
| FAB | Add (+) button placement / floating button |
| CLT | Too many buttons/icons/clutter in chrome (toolbar, header) |
| X | Not about app navigation (e.g. kitchen drawer, "menu" = food menu, browser tabs, spreadsheet tabs as content) |
Context flag appended in note: [habit] [todo] [native] from folder.
| TABF | Wants a feature (notes, calendar, stats, goals) as its own tab/section — tab as mental model for "a place" |
| TABG | Wants habit groups/categories shown as tabs/pages (grouping need; see Day Structure report) |
| NAVL | Hard to navigate at first, learned after a few days (learnability) |
| HIDS | Subscription / cancel option hard to find (billing findability, not app structure) — used in samples |
