## 1. The design on one page

1. **Every fresh install asks first:** "New here" or "I've used this before", *before* onboarding. The second path offers:
   - **Sign in** (Plus): everything returns from the server;
   - **Import a file** exported from the old phone.
2. **The OS's own transfer is supported and detected.** Quick Start, iCloud restore, Android device-to-device transfer and Samsung Smart Switch carry our data. We detect the arrival and say so, and the device gets a fresh identity (topic 3 §3.5). This is how most free users move.
3. **iPhone ⇄ Android without an account: an export file.** Settings → "Move to a new phone" explains the path for their situation in one screen:
   - **Plus:** "Sign in on the new phone";
   - **Free, same OS:** "Use your phone's transfer";
   - **Free, other OS:** "Export a file, send it to yourself (AirDrop, Nearby Share, email to yourself or a cloud drive), then Import on the new phone."
   The file is the open `.habits.zip` format (topic 3 §3.2), and either app imports the other's.
4. **Old phone gone:** Plus with an account signs in and everything returns. Everyone else relies on the phone's own backup (same OS) or a file they exported. The "Getting a new phone?" help says this honestly, before it's needed.
5. **Premium always follows the person:**
   - same OS: through the store;
   - cross-OS: through the account. A Plus holder who skipped the account signs in on the old phone first (one tap).
6. **Nothing shrinks on a new phone.** No free limits, settings or history differ from the old phone (users show: limits "reset" on new phones).
7. **The old phone is never wiped automatically.**
8. **Our own big updates are migrations too.** Data upgrades in place, automatically, with no export/import chore (users show: "asked us to export and import our data ourself"). The details are in topic 8.

**Platform facts behind C and F:**
- **Apple's Move to iOS** copies contacts, messages, photos and the like, and re-downloads matching free apps, but **does not transfer third-party app data.**
- **Google's iPhone → Android copy** likewise re-downloads apps without their data.
- **iCloud data can't be read by an Android app.**

## 4. Import and export for moves

### 4.1 Flow
1. **Old phone:** Settings → **Move to a new phone** → **Export a file**. The share sheet offers AirDrop, Nearby Share, Save to Files, email to yourself, or a cloud drive.
2. **New phone:** "I've used this before" → **Import a file** (or Settings → Import). The file is parsed, its checksum and manifest are checked, then a **preview**: "From Maria's iPhone 13 · 86 habits · 1,240 check-ins". Then **Import**.
3. **Plus without an account moving to the other OS:** "Sign in so Plus comes with you" (one tap Apple or Google) on the old phone first. After that, signing in on the new phone brings everything; no file is needed.

### 4.3 Moving through the server with a code (10 Oct 2026, built)

**Old device:** Backup & Export → **Move to Another Device** shows an 8-character code (Crockford base32: no I, L, O or
U) and three steps. **New device:** the welcome's "I've used it before" → **Move from another device** → type the code.
The two can be anywhere with an internet connection; no account is needed.

How it works (`iOS/Habits/Backup/DeviceTransfer.swift`, `server/src/transfer.ts`), the same on every platform, so an
Android app can send and receive with an iPhone:

1. Both devices stretch the code: **PBKDF2-HMAC-SHA256**, password = the 8 characters (ASCII, capitals), salt =
   `com.oftenenough.app.transfer.v2`, **100,000 rounds, 64 bytes**. Bytes 0–31 are the **AES-256-GCM key**; the **ID** is
   the lowercase hex SHA-256 of bytes 32–63.
2. The old device makes a fresh, checked backup file (`Core/Backup File Format.md`) and seals `"OEX1"` + one byte for
   its account (0 none, 1 free, 2 Plus) + the file with AES-GCM (a random 12-byte nonce; sent as nonce ‖ ciphertext ‖
   16-byte tag), then `PUT /v1/transfer/<id>`. It asks `GET /v1/transfer/<id>/status` every 5 s (`waiting`, `received`,
   `gone`) and shows Done on `received`. Leaving the screen sends `DELETE`.
3. The new device stretches the typed code the same way, `GET /v1/transfer/<id>` (404: "That code doesn't match, or it
   has expired"), opens it with the key (GCM refuses anything damaged or sealed with another code), checks the backup
   file, then `POST /v1/transfer/<id>/received`, which deletes it from the server. It restores like any backup file:
   a preview when the device has habits, Replace when it's empty, an undo file for 30 days (D5).

**What the server knows:** an ID and ciphertext, for at most an hour (refused and deleted after; the daily cron removes
leftovers), 25 MB at most, 60 requests a minute per IP (`TRANSFER_LIMIT`), so codes can't be guessed online. The server
never has the code or the key; finding the code from the ID costs 100,000 rounds per guess. **Cost:** one R2 upload and
one download a move, with files kept for minutes: about $0 inside the plan's included amounts, a few dollars a million
moves beyond.

**Limits:** both devices need the internet, and the old one must keep its screen open until Done (WhatsApp's own chat
transfer is local and needs both phones together; this doesn't). A lost or broken old phone can't send: then iCloud,
the account or an exported file are the ways back (§3).

### 4.2 Safety rules
- **Import previews and never destroys:** a snapshot of the new phone's data is taken first (topic 3 §3.6). It is *Replace* when the new phone is empty and *Merge* otherwise.
- **The old phone keeps its data** until the user removes it.
- **No second account is created silently** (topic 1).

## 5. Other rules

- **One obvious place:** "Move to a new phone" and "I've used this before" are always in the same spots on both platforms. The in-app help explains each path with pictures (users show: praise for clear instructions, `P84#14111`; complaints about unfindable transfer options, `A10#53474`).
- **Plan terms follow the person, not the install.** Nothing depends on the install date (users show: `A4#2374`, `P4#25223`).
- **The same features on both platforms** (ledger C251; users show: `P130#267`, `N11#2122`). A move should never lose a feature.
- **"Getting a new phone?" help:** one screen that explains the best path for their situation (signed in or not, same OS or not, Plus or not), reachable from Settings and from the in-app help.
- **Support never needs to move data by hand.** Plus users sign in; free users have the file.

## 7. Test checklist
1. **iPhone → Android, free:** export a file, import it on Android; everything arrives, with a preview first.
2. **Android → iPhone, Plus with an account:** sign in on the iPhone; everything and Plus arrive.
3. **Plus without an account, iPhone → Android:** the move screen asks for a one-tap sign-in on the old phone first, and Plus arrives.
4. **Import into a phone that already has data:** a Merge preview, a snapshot taken, and no duplicates.
5. **Quick Start, Pixel transfer and Samsung Smart Switch:** data present, "came across" message shown, new device ID, a one-tap continue for signed-in users.
6. **Lost phone, Plus with an account:** sign in on the new phone and everything returns. **Lost phone, free, same OS:** restoring the phone's own backup brings the data.
7. **iPhone → Android with the old phone lost, no account:** the help screen explains that only an exported file can cross over, and importing one works.
8. **Free limits and settings on the new phone are identical** to the old phone.
9. **Move with a code through the server** (§4.3): two devices on different networks (one on mobile data); a wrong
   code and an expired one (after an hour) say "That code doesn't match"; leaving the old device's screen deletes the
   file; the new device with habits gets a preview first; iPhone ⇄ Android once there's an Android app. On GitHub:
   OnboardingUITests' `testMoveFromAnotherDeviceThroughTheServer`, BackupCheck's `transferFailures`, the server's
   `transfer.test.ts` and `server-dev-checks.yml`.
